## 诊断：CineEye 训练效果不满意的原因

现状指标（真实 6 部电影，feature 模式，CPU）：val top1=0.7875，test 帧级 top1=0.8583，视频级=1.0（仅 6 段样本），sklearn 基线 0.6。

**结论：主因是硬件限制 + 任务本身难度（同类型片），不是代码 bug。**

关键证据：
- 无 GPU（nvidia-smi 不存在，torch 2.9.1+cpu，cuda=False），只能 feature 模式冻结主干；仅缓存 resnet18 权重。
- 在现有 512 维冻结特征上跑 logreg / LinearSVC / RBF-SVC 对照，val 恒在 0.76~0.80、test 0.79~0.85 → 瓶颈在特征判别力，不在分类头。
- movie_id_map 显示 6 部均为同类型成人电影，色调/场景高度相似 → 类间易混（movie_03/05 互混最重），ImageNet 通用特征难区分。
- 训练跑满 40 epoch（checkpoint 实际 epochs=40，非 default.yaml 的 60），best_epoch=38，早停无异常。

代码审查未发现致命 bug：按 video_id 分组防泄漏、特征内容签名缓存、BN 强制 eval、RGB 转换、ImageNet 归一化均正确。

次要可优化项（非 bug）：抽帧长边仅 256 且 resize 成 224×224 方形拉伸；feature 模式下 augmentation 配置完全不生效；每类仅 240 训练帧；val loss 选 best 而 val 样本仅 40/类，波动大。

改进建议排序：① GPU + finetune（最有效，当前硬件做不到）② --long-edge 320~384 重抽帧 ③ 换 resnet50/efficientnet_b0（需下载权重）④ --segments 12 --frames-per-seg 60 增数据 ⑤ 扩大 test 段数再评估（视频级 1.0 样本太小）。

## 修复 git push 失败（用户报 "Connection closed by 198.18.0.14 port 22"）
- 两层问题，缺一不可：
  1. **网络层**：DNS 被劫持，github.com/ssh.github.com 解析到 198.18.0.x（RFC2544 保留段），22 端口被关；公共 DNS 也被劫持，写 hosts 无效。HTTPS 443 正常。解法=走 GitHub 官方 SSH-over-HTTPS：ssh.github.com:443 + 本机 HTTP 代理 CONNECT 隧道（代理地址取自 https_proxy 环境变量，WorkBuddy 注入的 127.0.0.1:37851）。
  2. **仓库层（真正的卡点）**：初始提交误把 .cache/(497M pip 缓存) 和 .Trash-0/(222M,含 176M torch wheel) 共 347 个文件提交进 git，.git 达 604MB，push 传不动。用户选"重写初始提交"：.gitignore 补 /.cache/ 和 /.Trash-0/ → git rm -r --cached → commit --amend → git reflog expire --expire=now --all && git gc --prune=now --aggressive → .git 从 604MB 瘦到 536KB。
- SSH 配置细节：本机 /etc/ssh/ssh_config.d/ 属主是 nobody，OpenSSH 10.x 报 "Bad owner or permissions" 拒载配置，chown 被安全策略拦。绕过法=所有 ssh 命令加 `-F /dev/null`。
- 落地方案：项目内 .git-helpers/ssh-github.sh 包装器（shift 掉 git 传入的 user@host，固定连 ssh.github.com:443，ProxyCommand 用 ncat --proxy，UserKnownHostsFile=/dev/null）+ git config core.sshCommand 指向它。脚本已提交进仓库，换机器克隆后照样能 push。
- 结果：main 已推送，本地=远程 ddce13b，工作区干净。远程原本为空，--amend 无冲突风险。
