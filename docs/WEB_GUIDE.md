# 影瞳 Web 界面使用指南

> 两个 Web 页面：**用户前台**（上传即识别）+ **管理后台**（上传素材、打标签、触发训练、看进度）。
> 完整设计见 [WEB_UI_DESIGN.md](WEB_UI_DESIGN.md)。本文只讲怎么用。

---

## 1. 启动

```bash
cd /home/kylin/Workarea/CineEye

# 首次：构建前端（需 Node 22；依赖只需装一次）
cd web && npm install && npm run build && cd ..

# 启动服务（同一端口同时提供页面和所有接口）
./.venv/bin/python scripts/06_serve.py --port 8080 --with-identifier
```

然后浏览器打开：

- **用户前台**：<http://127.0.0.1:8080/>
- **管理后台**：<http://127.0.0.1:8080/admin>

> 局域网其他机器把 `127.0.0.1` 换成这台机器的 IP。服务默认监听 `0.0.0.0`。
> 若只构建了前端没构建后端接口，`/` 会返回一段 JSON 提示，按提示操作即可。

---

## 2. 用户前台（`/`）

1. 选择模式：**识别电影**（综合识别）或 **只认演员**（合影/生活照逐脸识别）。
2. 拖拽或点击上传一张图片 / 一段视频。
3. 点「开始识别」。
4. 结果卡片展示：片名、置信度、多语言别名、演员、识别出的人脸。

说明：
- 视频识别会先把视频上传到素材库再抽帧识别，首次稍慢；
- 演员照直接走演员识别接口，**不依赖**电影分类模型 `best.pt`；
- **识别门槛**：默认只有图库相似度 ≥ 80% 的候选才会显示（配置项 `identify.min_similarity`）。画面不够像时卡片区为空并提示"没有匹配到已知电影"——这是**故意的拒识**，避免出现低置信度的乱猜结果；训练/图库里的原图相似度≈100%，一定能正常识别。

## 3. 管理后台（`/admin`）

左侧四个菜单：

### 3.1 状态中心

一屏看模型类别数、图库图片数、电影档案数、演员数、素材总数、推理设备，每 5 秒自动刷新。

### 3.2 上传素材

拖拽/选择多个图片或视频 → 点「开始上传」→ 素材按内容 sha256 去重入库。上传后到「素材库」补标签。

### 3.3 素材库 / 补标

- 表格列出所有素材，支持按文件/标签/备注搜索，按**内容类型**（海报/剧照/花絮/演员照…）和**用途**（训练/查询/图库/参考）筛选。
- 点某行的「补标」打开右侧抽屉，按五层标签填写：
  1. **基础属性**：只读（系统自动提取的指纹/尺寸/时长等）；
  2. **内容分类**：内容类型、语言、地区；
  3. **语义关联**：关联电影（多选）、出镜演员（多选）、自由标签；
  4. **训练用途**：用途、数据集划分、分类标签、画质、人脸标记；
  5. **合规采集**：版权、肖像授权、备注（全部可选）。
- 保存后系统自动把标签**派生写回**到现有训练流程（电影画面→`movie_images` 表，演员照→派生清单）。

### 3.4 训练中心

- 选任务类型：电影识别模型 / 演员识别模型 / 重建图库 / 同步标签；
- 可填训练轮数（留空用默认）；
- 点「开始训练」立即返回任务号，页面不卡住；
- 任务列表显示状态徽章与进度，点某行看**实时日志**（每 2 秒刷新）；
- 运行中的任务可「取消」。

## 4. 接口速查（供脚本/二次开发）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api` | JSON 版服务发现 |
| GET | `/tag-schema` | 标签契约（五层字段/枚举/中文名） |
| POST | `/admin/upload` | 上传素材（`file_base64` + `file_name` + `tags`，或服务端 `path`） |
| GET | `/admin/assets` | 素材列表（`?kind=&purpose=&q=&limit=&offset=`） |
| GET | `/admin/assets/{id}` | 单个素材完整标签 |
| PATCH | `/admin/assets/{id}` | 补标/改标 |
| POST | `/admin/assets/{id}/archive` | 归档（软删） |
| POST | `/admin/train` | 触发训练（`{"kind":"train_movie","epochs":40}`）→ 返回 `task_id` |
| GET | `/admin/tasks` / `/admin/tasks/{id}` | 任务列表 / 状态+进度+日志 |
| POST | `/admin/tasks/{id}/cancel` | 取消任务 |
| GET | `/admin/status` | 状态中心汇总 |

所有接口返回 `{"ok": true, "data": ...}` 包络；失败返回 `{"ok": false, "error": "..."}`。

完整接口文档见 [API_GUIDE.md](API_GUIDE.md)。

## 5. 开发与重新构建

前端源码在 `web/src/`，改完重新构建：

```bash
cd web && npm run build && cd ..
```

开发模式（热更新，后端需另开在 8080）：

```bash
cd web && npm run dev     # 打开 http://127.0.0.1:5173
```

`vite.config.js` 已配好代理，dev 模式下所有后端请求自动转发到 8080。

## 6. 安全边界

当前定位为**仅本机/局域网自用，无登录**。若要对外开放，必须先补：

1. 登录鉴权（会话/token）；
2. CORS 白名单（现为 `*`）；
3. 上传路径白名单与大小限制（现默认 2 GiB，`CINEYE_MAX_UPLOAD_MB` 可调）；
4. 前置 nginx 限流。

相关注释已在 `cineeye/serve.py` 中标明。

## 7. 常见问题

**Q：打开 `/` 是一段 JSON 不是页面？**
前端未构建。执行 `cd web && npm run build`，刷新即可。

**Q：上传视频报"请求体超过限制"？**
base64 会放大文件约 33%。调大环境变量 `CINEYE_MAX_BODY_MB`（默认 256）后重启服务；或让运维把视频放到 `data/uploads/` 后用 `path` 方式登记。

**Q：点了训练，日志一直没动静？**
看任务状态：queued 表示在排队（并发上限 2）；running 但无日志说明子进程还在初始化（模型加载）。任务失败会显示 `failed` 和退出码，日志尾部有堆栈。

**Q：补标后训练数据没变？**
补标只写 `assets` 与派生清单；真正训练读的是 `data/manifest.csv` / `data/actors/manifest.csv`。触发对应训练任务时会重新生成这些清单。若只想同步派生，选「同步标签到现有流程」任务。
